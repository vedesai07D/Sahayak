How the current hybrid TTS works (facts, from src/lib/speech.ts and callers):
- ListenButton is used in exactly 3 places:
  * src/routes/learn.$lessonId.tsx  -> audioKey = lesson id (28 lessons)
  * src/routes/safe.$storyId.tsx    -> audioKey = story id  (7 stories)
  * src/routes/dictionary.tsx       -> NO audioKey (always browser TTS)
- Audio is only used if the key is listed in public/audio/manifest.json
  under the matching language array, with the file at public/audio/<lang>/<key>.mp3.
- Lesson playback text = title + description + all steps joined.
- Story playback text = title + story body + warning signs + key lesson.
- NOTE: the Emergency page, Onboarding, Help Topics, quizzes and scenarios
  currently have NO listen button / audioKey, so recordings for those would
  be unused until a code change adds one. They are therefore NOT in the
  record-now list.

- Marathi + Hindi: recorded audio is genuinely worth it. Browser hi-IN / mr-IN
  voices are often missing or robotic on budget Android phones, and these are
  the primary languages of the target elderly users.
- English: SKIP recorded audio for now. en-IN browser voices are widely
  available and acceptable. Recommend 0 English recordings in the initial release.
